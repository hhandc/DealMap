# DealMap implementation plan

**Goal:** Deliver the approved Korean franchise deal discovery prototype.
**Architecture:** Next.js static export; one client working surface with separate map, cards and dialogs. Zustand state is mutated only by DealActions. Local browser storage retains device-local favorites and personal reward records.
**Tech Stack:** Next.js 15, React 19, TypeScript, Tailwind v4 semantic tokens, Zustand, Radix, Lucide.
**Spec:** docs/superpowers/specs/2026-09-11-dealmap-design.md

## Tasks
- [ ] Create initial app shell, sample data, cards and neighborhood map; show first meaningful local preview.
- [ ] Add shared search/category/sort selectors, favorites, pan/zoom/recenter and detail dialogs.
- [ ] Add explicit demo login, expandable sample coupons, stamp progress and validated local personal records.
- [ ] Verify selector combinations, coupon/stamp validation, persistence handling, lint, typecheck and production export.
- [ ] Publish the exact tested static output privately through Sites.

## Boundaries and acceptance
`src/features/dealmap/data.ts` defines sample Deal records. `model.ts` provides pure filtering and validation; `store.ts` owns state; `actions.ts` owns mutations and persistence. Components call actions and read selectors. `src/components/ui` contains reusable Radix primitives. `src/styles/globals.css` owns semantic tokens and responsive composition. Test empty/mixed-language search, combined filters, expiry sorting and invalid reward entries; verify the production output contains an index and all local assets.
